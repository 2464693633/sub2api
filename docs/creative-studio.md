# 图片与视频创作画布

创作入口为 `/studio` 中的「无限画布」。本版把图片生成、细节派生、图片转视频和短片导出放进同一个项目；项目、素材、任务保存在服务器，刷新或关闭页面后，已经提交的任务继续执行。

原有生图、视频、提示词库和资产页签仍可使用。旧页签保存在浏览器中的历史不会自动上传，可以在画布的「从素材添加」中选择「浏览器中的历史作品」并导入。

## 使用方法

### 生成一张整体图和四张细节图

1. 打开画布，创建或选择一个项目。
2. 点击「整体 + 4 张细节」。画布会放入一张整体图卡片和四张细节图卡片，并连接引用关系。
3. 打开「项目设置」，填写统一主体和风格，选择图片默认模型、分组、画幅，以及视频默认模型、时长和分辨率。新建卡片默认继承这些参数。
4. 选中整体图补充整图要求，再调整各细节卡片的提示词，例如材质特写、接口特写、背面和结构细节。需要独立模型或画幅时，把该卡片的参数来源改为「单独设置」。
5. 点击「检查生成计划」，确认图片／视频总数、前置步骤、参考来源和错误。点击「生成待完成步骤」时服务器还会重新检查，再先生成整体图、用整体图作参考生成细节；独立任务在服务器的并发限制内执行。
6. 可以单独重试失败步骤，或对选中的卡片批量生成另一版。模型必须支持相应的参考图生成能力。

「添加文字」可以创建共用提示词。将文字连接到图片或视频卡片后，生成时会将其与目标卡片自身的提示词合并。

### 项目设置、预检和批量操作

- 主体和风格会加入每个图片、视频任务的实际提示词，再结合连接的文字和卡片自身提示词。这里只提供统一创作方向，主体一致性仍受所选模型的参考图能力影响。
- 新卡片继承对应的图片或视频默认参数；旧项目中没有继承标记的卡片仍使用原有独立参数。可以对全部卡片或选中的卡片应用项目默认值，也可以随时切回独立参数。
- 模型参数面板按已知接口能力显示尺寸、质量、格式、时长、分辨率和参考图数量。Grok 图片不显示 OpenAI 的质量／格式控制；DALL-E-3 不接受图片参考。未知模型或自定义映射保留可配置参数，建议值不代表所有上游都接受。
- 预检计算包含需要自动生成的前置图片，显示各步骤引用的素材或待生成卡片。它检查图结构、参数、当前用户的分组权限、已有任务和队列限制，不会创建任务、密钥或调用生成模型；不提供精确费用预估，也不能保证之后上游账号仍可用。
- 执行前对整条生成链再次检查，任何步骤参数或分组权限不合法时，整批不会部分入队。已经提交的任务固定当时的参数，之后修改项目设置不会改动它们。
- 框选或勾选多个卡片后，可以统一应用默认参数、生成所选版本、加入时间线，或为选中的图片分别派生视频。
- 手机默认使用卡片列表，也可以切回画布。画布新卡片可自动定位，连线会尽量绕过其他卡片；卡片重叠时仍可能没有足够空间完全避让。


### 从图片生成视频

图片卡片的「生成视频」会在右侧创建视频卡片并连接参考关系。在视频卡片中填写镜头动作，例如“缓慢推进，保持产品外观不变”，选择视频模型、时长和分辨率后生成。

已生成图片、上传图片以及从旧工作台导入的图片均可作为参考。也可以选中多张图片，为每张分别创建视频卡片。每个视频任务当前最多接受一张参考图；每个图片任务最多接受八张参考图，具体模型还可能有更严格的限制。

本版没有首尾帧配对、多参考图视频、视频截帧和视频续长控制。连线目前支持「文字 → 图片／视频」和「图片 → 图片／视频」，不接受自环、重复连接和循环依赖。

### 素材和版本

- 画布卡片引用服务器素材编号。图片缩略图和视频预览地址只在当前浏览器会话中使用，不作为持久保存的素材来源。
- 所有成功生成的版本保留在项目素材中。在右侧版本列表可以切换回旧版本；图片支持两版并排对比、标记满意版本。标记会保存到项目，时间线已使用的版本不随标记变化。
- 提交任务时会固定提示词、参数和输入素材。运行期间修改卡片或切换参考版本，不会改变已经提交的任务。
- 已生成的前置结果会直接作为参考。如果任务已成功但浏览器还没把素材编号写回画布，服务器会使用任务中保存的成功结果，避免再次生成同一前置图片。
- 没有结果、且从未运行过的前置卡片可以自动补跑。前置卡片已有失败、取消或结果未知的历史任务时，需要先重试该任务或选定一个已完成版本；从后续卡片运行不会隐式重新提交这些前置任务。
- 时间线保存的是选定的素材版本。重新生成画布卡片，不会自动替换已加入时间线的镜头。

### 时间线导出

在有结果的卡片上点击「加入时间线」，然后调整镜头顺序、视频起点、镜头时长和字幕。图片作为静态镜头使用。可以上传音频作为背景配乐，导出时会与镜头原声音混合。

「预览时间线」在浏览器中顺序播放所选素材和裁剪区间，便于检查镜头安排；最终字幕样式、编码和混音以导出的 MP4 为准。可选择当前项目的一张图片作为封面，导出时将封面作为 `attached_pic` 写入 MP4，不增加片头镜头或改变成片时长。不同播放器对内嵌封面的显示方式不同。封面、配乐和镜头都固定到提交时选定的素材版本。

当前导出限制如下：

| 项目 | 限制 |
| --- | --- |
| 镜头数量 | 1–12 个 |
| 单镜头时长 | 1–30 秒 |
| 总时长 | 最多 90 秒 |
| 输出画幅 | 1280×720、720×1280、720×720 |
| 输出格式 | MP4，H.264 视频和 AAC 音频，30 fps |
| 源素材尺寸 | 单边不超过 8192 像素，总像素不超过 3200 万 |
| 导出文件 | 最大 128 MiB |

视频裁剪范围必须在原视频时长内。导出复用已选素材，不重新调用图片或视频生成模型。本版提供顺序拼接、裁剪、字幕和背景音乐，尚未提供复杂转场、可编辑多轨或多人协作。

## 任务、费用和恢复

生成通过项目现有网关执行，继续使用用户允许的分组、账号调度、余额检查和正常用量计费。画布不会绕过网关，也不会在项目文件中存放明文 API Key。创建卡片、连线、上传素材和本地视频合成本身不调用生成模型。

一次批量提交可能生成多个图片或视频，每个实际生成任务分别计入模型用量。生成另一版会创建新的生成请求；费用以实际模型和分组计费为准，本版不提供精确费用预估。接口支持幂等请求编号，提交响应丢失后重试同一编号可以取回原批任务，避免再次提交。

| 状态 | 含义和处理 |
| --- | --- |
| 排队中 | 已保存到服务器，等待执行名额 |
| 等待前一步 | 依赖的生成任务尚未完成 |
| 生成中 | 已开始调用上游或正在合成 |
| 已完成 | 结果已保存为服务器素材 |
| 失败 | 查看错误信息；前置失败会阻止后续分支继续生成 |
| 已取消 | 当前任务已停止排队或执行；已经发送给上游的请求不保证能撤销或退费 |
| 需要确认重试（`interrupted`） | 无法确认上次提交是否已被上游接受，需要先检查用量和上游结果，再决定是否重新生成 |

视频任务取得上游编号后，会先持久保存编号，再查询进度。轮询或下载失败时，重试继续取回原视频；上游明确返回失败、过期或取消时，重试创建新的生成任务。

服务器重启后，已排队的任务继续排队，依赖关系继续保留；已记录上游编号的视频继续轮询。无法确认结果的运行中图片，以及尚未记录上游编号的视频，标记为 `interrupted`，不会自动再次 POST。重试失败前置任务后，仅恢复因该前置任务受阻的分支，不重做其他已成功结果。

项目保存使用版本号校验。另一个浏览器标签页修改了项目时，旧标签页不会直接覆盖新版本；界面会提示冲突，可以先导出当前草稿，再重新加载服务器版本。未成功保存的编辑会尽量保留在当前用户的浏览器草稿中；跨设备使用依赖成功保存到服务器的版本。

## 服务器运行要求

### 数据目录与备份

数据位于配置项 `pricing.data_dir` 下的 `creative-studio` 子目录。`pricing.data_dir` 默认是相对于进程工作目录的 `./data`。目录结构为：

```text
<pricing.data_dir>/creative-studio/
  .lock
  <用户 ID>/
    <项目 ID>/
      project.json
      assets/
        <素材 ID>
```

`project.json` 保存画布、时间线、任务、素材元数据和幂等记录；`assets` 保存实际媒体内容。写入先落临时文件，再原子替换。文件只通过经过用户认证的素材接口提供，不应将这个目录直接暴露为静态网站。

部署或迁移时必须保留整个目录。容器部署需要把 `pricing.data_dir` 挂载到持久卷；只备份 PostgreSQL 或只备份应用二进制都无法恢复画布素材。数据库也应照常备份，以保留用户、分组、工作台密钥和计费记录。迁移后保持用户 ID 与目录对应。

推荐在维护窗口停止服务后复制或归档 `creative-studio` 整个目录，再启动服务。也可以采用能保证跨文件一致性的文件系统快照。在线逐个复制文件可能得到素材与 `project.json` 不在同一时点的备份。

恢复时停止服务，恢复同一份备份中的项目文件及素材，确保运行用户具有读写权限，然后启动服务。启动恢复规则同上：已记录编号的视频继续查询，无法确认提交结果的任务需要人工检查。目录中的 `.lock` 使用操作系统文件锁，进程退出会释放；不需要通过删除文件强行解除正在运行的实例锁。

### FFmpeg 和字体

图片、视频生成使用已配置的上游模型。时间线导出在当前服务器调用 `ffmpeg` 和 `ffprobe`，要求可从服务进程的 `PATH` 找到，且 FFmpeg 提供 `libx264` 和 AAC 编码器。字幕优先使用以下字体之一：

1. `/usr/share/fonts/truetype/wqy/wqy-zenhei.ttc`
2. `/usr/share/fonts/wqy-zenhei/wqy-zenhei.ttc`（Alpine）
3. `/usr/share/fonts/opentype/noto/NotoSansCJK-Regular.ttc`
4. `/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf`

中文字幕建议安装文泉驿或 Noto CJK；只有 DejaVu 时中文可能显示缺字。Debian/Ubuntu 可通过系统包安装 `ffmpeg` 和 `fonts-noto-cjk` 或 `fonts-wqy-zenhei`。

仓库中的 Alpine Docker 运行镜像已加入 `ffmpeg` 和 `font-wqy-zenhei`。Alpine 字体文件位置参见其[官方软件包文件清单](https://pkgs.alpinelinux.org/contents?name=font-wqy-zenhei&repo=community&arch=x86_64&branch=v3.22)。

合成使用临时目录，完成或失败后删除临时文件。需为临时磁盘和数据目录预留空间。编码限制为单线程，全局同时只执行一个视频合成；图片和视频上游任务的总执行并发为 2，每个用户最多占用 2 个执行名额。等待合成名额的任务也计入执行并发。

### 容量与部署边界

默认限制如下，当前由 `creativestudio.Options` 和路由配置控制：

| 项目 | 限制 |
| --- | --- |
| 每用户项目数 | 200 |
| 每项目卡片数 | 100 |
| 每项目连线数 | 最多 400 |
| 每项目活动任务 | 50 |
| 每项目累计任务 | 5000 |
| 每项目素材数量 | 10000 |
| 每用户存储总量 | 1 GiB，包含素材及项目／任务 JSON |
| 单图片 | 32 MiB |
| 单视频或音频 | 128 MiB |
| 图片生成参考图总量 | 64 MiB |

素材和成功旧版本会继续占用配额。本版没有自动清理旧版本或管理员容量管理界面，应监控数据目录的空间。界面支持删除项目，但只允许删除没有活动任务的项目；删除会一并移除其素材与任务记录。

本版使用本机文件存储和单进程队列。对同一目录使用独占文件锁，第二个进程不会同时执行该目录中的任务；它的创作项目接口会返回服务不可用，避免重复生成。**这套实现不支持多个应用实例同时共享目录执行任务**，也不应使用没有可靠文件锁和原子重命名语义的共享文件系统。扩展为多实例部署前，需要将项目和任务状态迁移到数据库／任务系统，并把媒体迁移到对象存储。

应用关闭时，创作队列先取消并等待执行器退出，之后才关闭网关后台服务、Redis 和数据库。读取损坏项目文件、目录权限错误或无法取得独占锁时，创作接口不可用；应用会记录初始化错误，其他 API 可以继续启动。

## 接口和兼容性说明

项目 JSON 新增可选的 `settings`：`subject`、`style`、`image_params`、`video_params`。卡片 `data.paramsMode` 可为 `project` 或 `custom`；缺失时按旧版独立参数处理。`data.preferredAssetId` 保存满意版本，时间线 `cover_asset_id` 保存封面；二者均校验属于当前用户的当前项目，且素材类型正确。

- `GET /api/v1/studio/projects/capabilities?kind=image|video&model=...&platform=...` 返回当前工作台参数建议、可编辑控制和参考数量；视频 `max_seconds` 为该模型可提交的时长上限。已知 `grok-imagine-video`、`grok-imagine-video-1.5` 上限为 15 秒，未知模型保留工作台 30 秒总上限，是否支持仍由上游判断。
- `POST /api/v1/studio/projects/:project/preflight` 接收 `{node_ids, revision}`，返回 `valid`、包含前置步骤的 `counts`、实际提示词／参数／输入来源，以及按卡片归属的 `errors`。旧版本号返回冲突，预检不写入任务。
- 生成接口和预检使用相同的依赖规划器；入队前会再次验证当前用户允许的图片／视频分组。自定义模型别名不因未出现在默认模型列表而被预检拒绝。
- 视频参数在画布项目中仍保存为 `seconds` 和 `size`。发送到当前 Grok 视频网关时转换为官方 `duration`、`aspect_ratio`（例如 `1280x720` 转为 `16:9`），参考图使用 `image.url`。原网关解析器兼容顶层 `image_url`，但它只用 `duration` 读取生成时长，不能用 `seconds` 代替。
- Grok 图片尺寸继续传给现有网关，由网关转换为画幅和 1K／2K 分辨率。工作台不再丢弃用户选择的图片尺寸，仍不向 Grok 发送 OpenAI 的质量和输出格式参数。
